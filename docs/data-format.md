# مشخصات فرمت داده‌ها

این سند «قرارداد» بین ابزار (`index.html`) و هر چیزی است که داده می‌سازد (اسکریپت‌ها، فایل‌های دستی، مشارکت‌کننده‌ها). اگر خروجی‌ات با این فرمت‌ها بخواند، ابزار آن را بدون هیچ تغییری می‌پذیرد.

## ۱. فایل بانک (JSON) — فرمت اصلی

```json
{
  "format": "entekhab-reshte-bank",
  "version": 1,
  "meta": {
    "title": "ریاضی و فنی ۱۴۰۵",
    "group": "ریاضی و فنی",
    "year": 1405,
    "rows": 4174,
    "note": "توضیح اختیاری",
    "source": "نام اسکریپت یا منبع"
  },
  "bank": [ { "code": "30001", "major": "…" } ]
}
```

| فیلد سطح‌بالا | الزامی؟ | توضیح |
|---|---|---|
| `format` | توصیه می‌شود | مقدار ثابت `entekhab-reshte-bank` |
| `version` | اختیاری | فعلاً `1` |
| `meta` | اختیاری | فقط برای نمایش (عنوان در پنجره‌ی بارگذاری و فهرست بانک‌های آماده) |
| `bank` | **بله** | آرایه‌ی رکوردها |

ابزار یک **آرایه‌ی ساده‌ی رکوردها** (بدون پوشش بالا) را هم می‌پذیرد.

> ⚠️ فایلی که کلید `items` (آرایه) هم داشته باشد «پشتیبان کامل» حساب می‌شود (بخش ۴) و در بارگذاری، لیست و نتیجه‌ی کاربر را جایگزین می‌کند. در فایل بانک **`items` نگذار**.

### رکورد (هر ردیف = یک کد رشته‌محل)

| فیلد | نوع | الزامی؟ | توضیح |
|---|---|---|---|
| `code` | رشته | **بله** | کد رشته‌محل، ارقام ASCII (۴ تا ۶ رقم). **یکتا** باشد. |
| `major` | رشته | **بله** | عنوان رشته |
| `university` | رشته | | نام دانشگاه/مؤسسه (در صورت نیاز با پردیس، مثل «دانشگاه X - تهران») |
| `province` | رشته | | استان |
| `admission` | رشته | | نحوه پذیرش (مثل «با آزمون»، «صرفا با سوابق تحصیلی») |
| `degree` | رشته | | دوره تحصیلی (روزانه، نوبت دوم، …) |
| `gender` | رشته | | جنس پذیرش، مثل «مرد و زن» / «مرد» / «زن» |
| `capFirst`, `capSecond` | رشته | | ظرفیت نیمسال اول/دوم (خالی = ندارد) |
| `capFemale`, `capMale` | رشته | | ظرفیت اختصاصی هر جنس، اگر جدا اعلام شده |
| `notes` | رشته | | توضیحات ستون آخر دفترچه (متن کامل) |
| `star` | بولین | | بلوک «ستاره‌دار» (مثلاً مصاحبه/گزینش) |
| `page` | رشته | | شماره‌ی صفحه‌ی دفترچه، برای ردیابی |
| `blockRaw` | رشته | | عنوان خام بلوک در دفترچه |
| `src` | رشته | | فقط `"native"` برای ردیف‌های مخصوص بومی |
| `domain`, `service`, `nativeProvince` | رشته | | فقط برای `src: "native"`: دامنه‌ی پذیرش، محل خدمت، استان بومی |

قواعد:
- مقدارهای غیررشته‌ای (عدد) به رشته تبدیل می‌شوند؛ `null` به رشته‌ی خالی.
- ردیفی که `code` یا `major` نداشته باشد نادیده گرفته می‌شود.
- هنگام ذخیره، ردیف‌ها بر اساس `code` یکتا می‌شوند. در حالت «افزودن»، ردیف هم‌کد با نسخه‌ی جدید جایگزین می‌شود.
- پیشنهاد برای تولیدکننده‌ها: ارقام ASCII، «ی» و «ک» فارسی، بدون نویسه‌های جهت‌نما (RLM/LRM). نیم‌فاصله اشکالی ندارد.

## ۲. CSV / Excel

- کدگذاری UTF-8 (با یا بدون BOM) یا Windows-1256؛ جداکننده‌ی کاما، سمی‌کولن یا Tab (خودکار).
- سطر هدر خودکار پیدا می‌شود. نام ستون‌ها (فارسی) با این الگوها تشخیص داده می‌شوند:

| فیلد | نام ستون |
|---|---|
| `code` | شامل «کد رشته» |
| `major` | شامل «عنوان رشته» |
| `university` | دقیقاً «دانشگاه» |
| `province` | دقیقاً «استان» |
| `admission` | شامل «نحوه پذیرش» |
| `degree` | شامل «دوره تحصیلی» |
| `gender` | شامل «جنس پذیرش» |
| `capFirst` / `capSecond` | «ظرفیت اول» / «ظرفیت دوم» (یا فقط «اول» / «دوم») |
| `capFemale` / `capMale` | «ظرفیت زن» / «ظرفیت مرد» (یا فقط «زن» / «مرد») |
| `notes` | شامل «توضیحات» |
| `star` | شامل «ستاره»؛ مقدار «بله» / `1` / `true` |
| `page` | با «صفحه» شروع شود |
| `src` | دقیقاً «نوع ردیف»؛ مقدار حاوی «بومی» یعنی ردیف بومی |
| `domain` / `service` / `nativeProvince` | با «دامنه» شروع شود / شامل «محل خدمت» / شامل «استان بومی» |

- اگر ستون «دانشگاه» نباشد، ابزار سطرهای عنوان بلوکی به شکل «استان X – دانشگاه Y» را به‌عنوان دانشگاه/استان ردیف‌های بعدی می‌خواند (فرمت اکسل‌هایی که مستقیم از PDF می‌آیند).
- نمونه: [`data/riazi-1405.csv`](../data/riazi-1405.csv)

## ۳. `data/manifest.json` (بانک‌های آماده)

```json
{ "datasets": [ { "id": "riazi-1405", "title": "ریاضی و فنی ۱۴۰۵",
                  "file": "riazi-1405.json", "csv": "riazi-1405.csv", "rows": 4174, "note": "…" } ] }
```

`file` نسبت به پوشه‌ی `data/` است. این فهرست فقط وقتی خوانده می‌شود که ابزار از طریق `http(s)` باز شده باشد (مثل GitHub Pages)، نه `file://`.

## ۴. پشتیبان کامل (JSON)

ساخته‌ی دکمه‌ی «💾 پشتیبان کامل». شامل `version` (فعلاً `5`)، `exportedAt`، `bank`، `items` (لیست رشته‌ها)، `sortSession`، `resultOrder` و `defaultStrategy`. بارگذاری‌اش **همه‌چیز را جایگزین** می‌کند. این فرمت برای استفاده‌ی داخلی ابزار است و ممکن است در نسخه‌های بعد عوض شود؛ برای تولید داده از آن استفاده نکن.

## ۵. فایل لیست نهایی (متن)

خروجی «⬇ دانلود» / «📋 کپی»، هر رشته در یک خط:

```
1. 30001 - مهندسی برق - دانشگاه … - استان — 📝 توضیحات (اختیاری)
2. ★ 30002 - علوم کامپیوتر - دانشگاه … - استان
```

قواعد ایمپورت («⬆ ایمپورت»):
- شماره‌ی ابتدای خط (`1.`، `۱)`، `(۱)` …) و `★` اختیاری‌اند؛ اگر ★ در فایل باشد، پرچم‌ها دقیقاً مطابق فایل تنظیم می‌شوند.
- خطی که فقط کد (یا چند کد با فاصله/کاما) باشد پذیرفته می‌شود؛ مشخصاتش از بانک پر می‌شود.
- تطبیق ابتدا با **کد** است، بعد با متن. اگر کدی در بانک نباشد، خط به‌صورت متن آزاد به لیست اضافه می‌شود.
- تکراری‌ها نادیده گرفته می‌شوند.
- حالت «جایگزین» ترتیب لیست نهایی را دقیقاً مطابق فایل می‌کند؛ حالت «افزودن» ته لیست اضافه می‌کند.
